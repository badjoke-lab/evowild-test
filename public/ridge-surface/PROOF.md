# 保守性の条件

対象は開始HEAD `2606922` の統合表面。元の24走行姿勢と静止姿勢、各LODの三角形索引、ボクセル色配列をロードする。試作で書き換えるものは実行時のGPU入力で、頂点の位置と三角形の順序は元の値を保つ。

## 三角形群

元メッシュの三角形を、重心の64モデル単位のセルで分類し、各群を最大24面に分ける。同じ姿勢・LOD内の三角形だけをまとめる。群の分類順を描画順として使うことはなく、最後に元の索引順で残す。

### 接地補正の境界

元の頂点シェーダーの補正は `x(t) = x0 + t × d`、`0 ≤ t < 1`。`d` は姿勢の接地ビットと頂点の高さで決まり、0以上となる。yとzは一定。全頂点のt=0とt=1の両端を含むAABBは、全補間区間と各三角形内の点を含む。姿勢ごとにこの境界を用意する。

### 視錐台

ワールド空間で内側が `N·X + D ≥ 0` の平面を考える。個体の回転R、スケールu、平行移動Tを使うとローカル空間の平面は `(u RᵀN)·p + N·T + D`。個体の現行の向きと走行位置から毎描画計算する。中心c、半径hのAABBにおける平面値の最大値は `a·c + b + |a|·h`。

ある一つの平面についてこの最大値が負なら、群全体がその平面の外側にある。バッチの全個体についてそれぞれ少なくとも一つの平面で外側と証明できた場合だけ、群を除外する。個体によって証明に使う平面は異なってよい。一個体でも可能性が残れば群を維持する。個体単位の既存視錐台テストで残ったバッチのみが対象となる。

### 群全体の裏面判定

既存実装が各三角形の接地補正の両端で求めた面平面 `n·eye − d` を用いる。各係数nの最小・最大とdの最小を群全体で集計する。バッチのカメラ位置の箱とnの区間積の最大を足し、dの最小を引くと、群の全端点の面について上界を得る。

この上界が既存の裏面判定の閾値−2より小さければ全端点が裏向き。X方向の補正について非正規化面平面の符号判定はtの一次式になるため、両端で裏向きなら補正途中でも裏向きとなる。正の長さによる正規化は符号を変えない。曖昧な群を維持し、その群の三角形だけに元の個別面判定を行う。群判定で落ちた面に個別面判定を再実行しない。

### 浮動小数点

GPUへの配置値はFloat32、境界計算はJavaScriptの倍精度。視錐台判定では境界を各軸2モデル単位拡張し、さらに正規化平面の最大値が−0.05ワールド単位未満の場合だけ除外する。これは今回の固定モデル・スケール・カメラでの量子化とFloat32の丸めに対する余裕。裏面は開始HEADの2モデル単位の余裕を引き継ぐ。非有限の値では比較が成立せず、除外しない。今回の保証の対象は既存のレースの有限な配置・カメラと既存のスケールである。

## 単色領域

各三角形の元のgrid座標を含む閉じたAABBを求め、各軸をさらに1ボクセル広げる。シェーダーと同じfloor、YZX並べ替え、paintOriginの減算、paintSizeによるclampを適用した整数範囲を列挙する。該当姿勢の元ボクセル配列からその箱の全セルを読み、全値が同じ場合だけ定色の候補にする。複数色の箱と縮退して既存faceShadeが非正の面は従来経路に残す。

透視補間やMSAAの評価点が三角形を外挿する場合にも対応するため、実際に画素シェーダーが算出したclamp後のセルが、証明した箱内にあるかを毎画素確認する。箱外ならtexelFetchを使う。既存の陰影フォールバック条件 `2 × fwidth(1/w) ≥ 1/w` が成立する画素も従来の色参照へ戻す。

箱内の全セルが同じ整数inkであり、選んだ画素セルが箱内にあるので、そのセルのtexelFetchと定数inkは等しい。17色パレットの参照と既存の陰影乗算は同じ式で実行する。色の境界、元の姿勢、ディザ、深度の処理はそのまま評価される。共有頂点の属性が他の三角形と異なる場合は、同じ座標のprovoking vertexを複製する。辺の形と画素被覆は同一になる。

この静的証明と毎画素の確認に加え、実際のゲーム投影で各試作の168組の前景マスク・RGBを開始HEADと比較する。
