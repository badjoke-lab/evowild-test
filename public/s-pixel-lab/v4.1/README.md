- 既存の17色と静止＋24走行姿勢を使い、原本の外面に沿って近・中景メッシュの頭冠と脚先を保護した。全73時点の頭冠IoU中央値は0.79575。スプライトと表面を混ぜる103–113pxの部分だけでは、3時点の中央値が0.72845→0.75000。正面・背面で区別できる脚先は原本186箇所中169→174。5視点×24姿勢の足元IoU最低値は0.65839→0.63871、尾部中央値は0.74574→0.70337。[全品質指標](evidence/quality.json)
- ディザ閾値を1画素も通らない側の送信を省略した。同じv4.1形状で3回ずつ対照試験を行うと、100体の移行集中時のGPU平均は54.99→42.56ms、全体p95は85.6→78.3ms。PC幅の2条件×48時点で、全移行を送信した画像、全三角形を送信した画像とのRGB差はそれぞれ0画素。[対照試験](evidence/coverage-ab.csv) · [画素照合](evidence/submission-check.json)

## 端末で測定する

1. デモZIPをPCで展開し、そのフォルダーから次を実行する。

   ```sh
   python3 -m http.server 8000 --bind 0.0.0.0
   ```

2. PCのWebGL 2対応ブラウザで `http://localhost:8000/` を開く。同じWi-FiのAndroidではChromeで `http://<PCのLANアドレス>:8000/` を開く。リポジトリから直接起動する場合は `python3 -m http.server 8000 --bind 0.0.0.0 --directory public` を実行し、パス `/s-pixel-lab/v4.1/` を開く。
3. 両端末・両版で同じ描画サイズを指定する。高DPR端末も指定した物理画素数で描く。端末名を入力し、ブラウザを前面に保ったまま「2条件を測定」を選ぶ。通常観察中は直近48フレームのFPS・p95と、描画個体数・近／中／移行／遠の内訳が出る。
4. 混在50体・100体が終了したら「JSONを保存」。完了画面のGPU名を確認する。v4とv4.1を切り替え、順序を交替して各3回保存する。端末名、ブラウザ版、電源・省電力設定を揃えて記録する。実機デモは端末のCPU速度を変更しない。

JSONには版、GPU名、ブラウザ、DPR、描画サイズ、平均FPS、p95、全96時点のカメラ、時刻、描画個体数、LOD内訳、三角形数、CPU送信・同期時間を含む。タイマー非対応時のGPU時間は `null`。タブが非表示になれば測定を中断し、不完全な結果の保存を防ぐ。

ZIP内の `evidence/review.html` で動画・拡大画像・反復別の測定値を閲覧できる。[再現用スクリプト](../../../scripts/s-pixel/v4.1/)
