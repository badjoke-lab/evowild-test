# P型2.5D 支持足帯の世界移動 — 実測判定

**判定: 距離連動周期は足滑り修正としてREJECT。本線は変更しない。**

実装変更を入れたのではなく、既存12枚の実RGBAと実レース画面の位置・移動データを使い、同じ位相の支持足帯が世界座標でどれだけ移動するか比較した。

- GitHub Actions run: https://github.com/badjoke-lab/evowild-test/actions/runs/38154282896 — SUCCESS
- スクリーンショット測定条件: 1方式あたり200点、各33ms、PC Chrome、同じ12相・同じ単体レビュー用レース
- 通常周期: 接地帯の同一フレーム内移動37区間、平均 **7.219px**、最大 **8.160px**
- 距離連動周期: 同38区間、平均 **7.328px**、最大 **8.160px**
- 可視データ: `support-band-travel.png`、生測定 `foot-world-trace.json`。
- 位置の推定方法: 走行シートの実アルファ（y=291–295）の最前方支持帯中心・レンダラーの実描画幅・ピクセル毎メートル・選択個体の世界距離を使う。
- **制約:** 足の個体識別・足首の追跡ではない。フレーム境界・支持足の切替を同一足として追跡できないため、これは本当の足底の絶対滑りではなく接地帯代理指標である。両方式は異なる位相配分で支持区間を通過するため、0.11px差を「確実に悪化した」とは断定しない。

**結論:** 距離同期試験は周期計算の整合テストをPASSしただけ。支持画像が描画中に前進し続ける現象に実効的な改善を証明できない。通常レースは既存方式を維持する。

次の*制作*方法は、ルート周期の数値調整ではなく、支持足の見える位置を固定できるレイヤー化／骨格ベースの脚アニメーションか、支持区間の絵の踏み替えと移動距離を同期させる専用スプライト制作。いずれも正規 `P.webp` の形態、接地、シルエットが合格するまでは候補止まりにする。
