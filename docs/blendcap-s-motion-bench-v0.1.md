## What BlendCap is being tested for

BlendCap is a single-video human performance-capture pipeline. It reconstructs body motion and exports BVH, then retargets that motion to Blender rigs.

For EvoWild, the test is **not** "human skeleton -> quadruped skeleton wholesale."

The useful candidate signals are:

- root travel
- pelvis drive
- center-of-mass rise/fall
- torso pitch / roll
- acceleration timing
- launch compression
- cadence / phase timing
- whole-body follow-through

The existing EvoWild quadruped gait remains authoritative for limb semantics and foot-contact behavior.

## Gate 0 — environment feasibility

Goal: determine whether a free source build is practical enough to continue.

Required checks:

- Blender 4.2+ available
- Python / dependency path compatible with the pinned BlendCap source
- at least 32 GB free working disk
- Git available
- capture model assets can legally and technically be obtained
- CPU-only or available GPU path identified
- no paid BlendCap build required for this experiment

Known constraint:

- official paid BlendCap build does not support macOS
- source builds on macOS are unsupported
- CPU-only capture exists but is expected to be slow
- NVIDIA is the validated fast path

## Gate 1 — video to BVH proof

Use one short clip only, approximately 2–4 seconds.

Preferred motion:

- low start
- explosive first steps
- visible torso and pelvis
- full body in frame
- minimal occlusion

Required artifact:

- real BVH generated by the pinned BlendCap source

If no usable BVH is produced, stop with `REJECT`.

No S retargeting before this gate passes.

## Gate 2 — motion decomposition

From the generated human performance, extract or reconstruct only the motion characteristics that can sensibly transfer to the S runner.

Do not directly map:

- human arms -> S forelegs
- human knees -> S hindlimbs
- human spine proportions -> S spine one-to-one

Candidate transferable channels:

- root translation
- root yaw/pitch/roll
- pelvis pitch/roll
- torso compression/extension
- torso pitch
- vertical oscillation
- launch timing
- cadence envelope

The existing S limb cycle and contact rules stay in place.

## Gate 3 — S hybrid render

Build a disposable hybrid clip:

`BlendCap-derived body signal -> S gait -> contact correction -> speed/cadence matching`

Required review views:

- SIDE
- LOW
- CHASE
- FRONT

Required checks:

- stance skating
- foot penetration / float
- fore/hind phase coherence
- root speed vs cadence
- pelvis drive
- shoulder/chest contribution
- spinal compression / extension
- neck/head follow-through
- launch posture
- high-speed readability

## Comparison baseline

Compare against the current Motion First S runtime, not against a skeleton preview.

A result is useful only if the rendered S motion is materially better in one or more whole-body categories without materially worsening contact quality.
